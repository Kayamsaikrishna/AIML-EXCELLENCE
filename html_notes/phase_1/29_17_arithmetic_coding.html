17. Arithmetic Coding

Encoding an entire message as a single point on a line.

1. Beyond Huffman

Huffman coding (Module 07) assigns an integer number of bits to each symbol. But what if a symbol only carries 0.5 bits of information? Huffman must round up to 1, wasting space. Arithmetic Coding** represents an entire sequence of symbols as a single Fraction (an interval) between 0 and 1.

2. The Fractional Interval

Each symbol narrows the current interval based on its probability. The final message is just a high-precision number within that tiny final interval. This method can reach the Shannon limit perfectly, even if symbol probabilities aren't "Clean" powers of 2.

3. AI/ML Connection: LLM Tokenizers and Neural Compression

The Perfect Bridge from Probabilities to Bits

In AI, Arithmetic Coding is the Standard for Modern Compression (H.264, JPEG2000, 7z)**.

When you build a Neural Compression model for images, the AI predicts the probability of each pixel. To turn those probabilities into an actual file, we pipe them into an Arithmetic Coder. In Natural Language Processing (NLP), concepts like Byte Pair Encoding (BPE) are pre-processors, but the final compression of "Language" into bits (for storage or transmission) relies on arithmetic schemes. Understanding this bridge allows AI engineers to build **Entropy-aware model formats**: we don't just store floats; we store the "Fractional intervals" of those floats. This is how Model Quantization (GGUF, EXL2)** works at its deepest level: it uses information-theoretic coding to pack as much "Intelligence" as possible into a single byte.
