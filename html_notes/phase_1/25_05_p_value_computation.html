Stats 1.5 Surprise Metric

P-Value Computation

Measuring how "surprising" your data is, assuming the boring explanation is true.

The Correct Meaning

A P-value is the probability of obtaining test results at least as extreme as the results actually observed, under the assumption that the Null Hypothesis is true.

- **Low P-value ( <0.05):** "Wow, this data would be very rare if nothing was happening. Therefore, something is likely happening (Significant)." - **High P-value (>0.05):** "Eh, this data is quite common even if nothing is happening. We can't conclude much."

WHAT IT IS NOT: - It is NOT the probability that the Null is false. - It is NOT the probability that the Alternative is true. - It does NOT measure the size of the effect.

1. Computation Workflow

1. Calculate your Test Statistic (e.g., \(z=2.5\)). 2. Look up the area in the tail(s) of the relevant distribution. 3. \(P = P(Z > 2.5) \) for a right-tailed test.

Small P-values mean your observed data is way out in the "tails," making it a statistical misfit for the Null Hypothesis.

2. ML Connection: Feature Selection

Supervised Interpretability

The "P-value" of a Feature

In Linear/Logistic Regression, Python libraries (like `statsmodels`) provide a P-value for every feature. - \(H_0\): This feature has NO effect on the target (\(w_i = 0\)). - \(H_a\): This feature DOES have an effect (\(w_i \neq 0\)).

If a feature has a P-value of 0.82, it means its relationship with the target is so weak that it could easily be random noise. We often Drop such features to simplify the model and prevent overfitting. Usually, we keep features with **P < 0.05**.

3. The "P-hacking" Danger

The Data Scientist's Sin

If you test 100 random features, 5 of them will have P < 0.05 just by pure luck! This is called **P-hacking**. In ML, this is the same as finding features that look good on one lucky split of the data but fail on the test set.
