18. Inverse Functions

Undo. Reverse. Reconstruct. The logic of Autoencoders.

1. The Mirror World

$$ f^{-1}(y) = x \iff f(x) = y $$

A function maps Input → Output. An inverse maps Output → Input. Geometrically, it is a reflection across the line \( y = x \).

Conditions

A function only has an inverse if it is One-to-One (Injective). If multiple inputs go to the same output (like \( x^2 \)), you can't know which one to go back to (unless you restrict the domain).

2. The Autoencoder

One of the most famous architectures in unsupervised learning is the Autoencoder. It tries to learn an Identity function \( f(x) \approx x \) by forcing data through a bottleneck.

$$ \underbrace{D}_{\text{Decoder}}(\underbrace{E}_{\text{Encoder}}(x)) \approx x $$

Here, the Decoder \( D \) attempts to learn the Inverse Function of the Encoder \( E \). If \( E \) compresses the image, \( D \) must un-compress it.

Generative Models (GANs/Flows)

Normalizing Flows explicitly use Invertible Neural Networks (INNs) where every layer is mathematically invertible, allowing exact likelihood calculation.

3. Coding an Autoencoder

A simple PyTorch Autoencoder compression.

// PyTorch: Autoencoder
import torch
import torch.nn as nn

class Autoencoder(nn.Module):
    def __init__(self):
        super().__init__()
        
        # Encoder: 784 -> 32 (Compression)
        self.encoder = nn.Sequential(
            nn.Linear(784, 128),
            nn.ReLU(),
            nn.Linear(128, 32) # Latent Space
        )
        
        # Decoder: 32 -> 784 (Reconstruction / Inverse)
        self.decoder = nn.Sequential(
            nn.Linear(32, 128),
            nn.ReLU(),
            nn.Linear(128, 784),
            nn.Sigmoid()
        )

    def forward(self, x):
        encoded = self.encoder(x)
        decoded = self.decoder(encoded)
        return decoded

# The Decoder learns to "Undo" the Encoder's compression.
