09. Adjusted R-squared

Punishing the bloat of meaningless features.

1. The R-squared Lie

Ordinary $R^2$ has a dangerous property: **it never goes down**. If you add a feature of "Random noise" to your model, the $R^2$ will technically increase by a tiny amount because even random noise can explain a coincidental fraction of the data. This leads to Overfitting.

2. The Adjustment

Adjusted $R^2$ penalizes the score based on the number of features $p$. It only increases if the new feature improves the model by more than what would be expected by chance.

$$ R^2_{adj} = 1 - \left[ \frac{(1 - R^2)(n - 1)}{n - p - 1} \right] $$

If you add a useless feature, $R^2_{adj}$ will actually **decrease**.

3. AI/ML Connection: Model Complexity and Feature Selection

Fighting Feature Bloat

In AI, Adjusted $R^2$ is the First line of defense against Overfitting**.

When performing **Forward Selection** (adding features one-by-one to an XGBoost or Regression model), we monitor $R^2_{adj}$. The moment it peaks and starts falling is exactly when the AI should stop adding features. This is the statistical equivalent of Occam's Razor**: simpler models are preferred. It is used in Hardware Optimization**: if an AI can achieve $R^2_{adj} = 0.90$ with 10 features but needs 1,000 features to get to $0.91$, the Adjusted score will favor the 10-feature model. This helps engineers deploy "Light" models on mobile devices that are just as effective but significantly faster and more energy-efficient.

4. Python: Comparison

# Function to compute adjusted R2
def adj_r2(X, y_true, y_pred):
    r2 = r2_score(y_true, y_pred)
    n, p = X.shape
    return 1 - (1-r2)*(n-1)/(n-p-1)

# As 'p' increases, this value will eventually plummet 
# if the new features are just noise.
