11. Squeeze (Sandwich) Theorem

Trapping a difficult limit between two easy ones.

1. The Concept

The Squeeze Theorem is used to find a limit of a function \(f(x)\) that is difficult to compute directly. If we can find two other functions \(g(x)\) and \(h(x)\) such that \(f(x)\) is always pinned between them:

$$ g(x) \leq f(x) \leq h(x) \quad \text{near } a $$

And if \(\lim_{x \to a} g(x) = L\) and \(\lim_{x \to a} h(x) = L\), then by necessity:

$$ \lim_{x \to a} f(x) = L $$

2. Classic Example: \(x^2 \sin(1/x)\)

As \(x \to 0\), \(\sin(1/x)\) oscillates wildly between -1 and 1. We cannot find its limit directly. However, we know:

$$ -1 \leq \sin(1/x) \leq 1 $$

Multiplying by \(x^2\):

$$ -x^2 \leq x^2\sin(1/x) \leq x^2 $$

Since \(\lim_{x \to 0} -x^2 = 0\) and \(\lim_{x \to 0} x^2 = 0\), the middle function must also approach 0.

3. AI/ML Connection: Performance Lower Bounds

Vizing the Worst Case

In Reinforcement Learning (RL) and Adversarial AI, we often cannot calculate the exact performance of a model because the environment is stochastic (wildly oscillating like \(\sin(1/x)\)). Instead, we build "lower bounds" and "upper bounds" on the performance.

If we can prove that the model's error is always squeezed between two functions that both collapse to zero as training time increases, we have proven that our model will definitely succeed, even if we can't track its exact path.

4. Python: Visualizing the Squeeze

import numpy as np

# f(x) = x^2 * sin(1/x)
# g(x) = -x^2 (Lower bound)
# h(x) = x^2 (Upper bound)

def f(x): return x**2 * np.sin(1/x)
def g(x): return -x**2
def h(x): return x**2

# Pick a tiny x
x = 0.0001
print(f"Lower bound g(x): {g(x):.12f}")
print(f"Function f(x):    {f(x):.12f}")
print(f"Upper bound h(x): {h(x):.12f}")

# f(x) is trapped!
