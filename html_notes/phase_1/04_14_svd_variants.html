14. Full vs. Compact vs. Truncated SVD

Optimizing memory and complexity in AI pipelines.

1. The Spectrum of SVD

Variant Dimensions (\(\Sigma\)) Best For
Full SVD \(m \times n\) Theoretical proofs and small matrices.
Compact SVD \(r \times r\) Removing explicitly dependent zero-rows/cols.
Truncated SVD \(k \times k\) Data Compression / Denoising.

2. Truncated SVD: The Best Approximation

Eckart-Young Theorem

If you want to represent a massive matrix using only \(k\) columns, the best possible approximation (in terms of Frobenius norm) is obtained by taking the largest \(k\) singular values and vectors from the SVD.

$$ \hat{\mathbf{A}} = \sum_{i=1}^k \sigma_i \mathbf{u}_i \mathbf{v}_i^T $$

This effectively filters out noise, as noise usually resides in the low-magnitude singular values.

3. Memory Savings

Storing a \(1000 \times 1000\) image takes 1M parameters. If we truncate to \(k=50\), we only store \( (50 \times 1000) + 50 + (50 \times 1000) \approx 100k \) parameters. A **10x compression**!

4. Python: Image Compression Simulation

import numpy as np

# A large synthetic data matrix
A = np.random.randn(500, 500)

U, s, Vt = np.linalg.svd(A)

# Truncate to k = 20
k = 20
A_approx = U[:, :k] @ np.diag(s[:k]) @ Vt[:k, :]

print(f"Full storage: {A.size}")
print(f"Compressed storage (approx): {U[:, :k].size + k + Vt[:k, :].size}")
