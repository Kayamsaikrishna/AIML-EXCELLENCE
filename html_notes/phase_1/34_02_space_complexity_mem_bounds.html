Space Complexity & Memory Bounds

Measuring Memory Consumption. Analyzing how much RAM or GPU VRAM is required to store model weights, activation maps, and intermediate states.

The VRAM Paradox

In deep learning, we often have enough time to train a model, but not enough memory. **Space Complexity** defines the total amount of auxiliary space required by an algorithm as a function of the input size. In AI, this is often the #1 bottleneck for "Mega-models."

1. Auxiliary vs. Total Space

  • Total Space: The memory for input data + the memory needed for computation.
  • Auxiliary Space: The extra or temporary space used by the algorithm (e.g., buffers, stacks, recursion state).
$$ \text{Space Complexity} = O(\text{Input Size}) + O(\text{Auxiliary Workspace}) $$

2. Memory Scaling in ML

Parameter Storage

A model with 7B parameters using 16-bit floats requires \((7 \times 10^9 \times 2)\) bytes \(\approx 14\) GB just to sit in memory. This is \(O(P)\) space where \(P\) is parameters.

Activations (The Hidden Cost)

During training, we must store the output of every neuron for the backward pass. For a layer of size \(N\) and batch size \(B\), we need \(O(B \cdot N)\) space. This "Activation Memory" is often larger than the model itself!

KV Cache (Inference)

In LLM inference, we cache previous token attentions. This grows linearly with sequence length: \(O(L \cdot d_{model} \cdot n_{layers})\).

Ops Hardware

Managing the Memory Wall

  • Gradient Checkpointing: Trading time for space. Instead of storing all activations (\(O(N)\)), we store only every few layers and recompute the rest (\(O(\sqrt{N})\)).
  • Mixed Precision (FP16/BF16/INT8): Reducing the bytes-per-parameter to halve or quarter the space complexity of model weights.
  • Data Parallelism (DP): Splitting the Linear Space requirement of batches across multiple GPUs.
  • Zero Redundancy Optimizer (ZeRO): Partitioning model states across GPUs so that each node only stores a fraction of the parameters, gradients, and optimizer states.

3. In-Place Algorithms

An algorithm is In-Place if it uses \(O(1)\) (constant) auxiliary space. In AI, this is rare because every operation (Matrix Mult) usually results in a new tensor. Library optimizations (like PyTorch's `inplace=True`) are efforts to turn \(O(N)\) operations into \(O(1)\) auxiliary ones.
