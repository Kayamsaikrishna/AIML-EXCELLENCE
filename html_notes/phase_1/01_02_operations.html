1. Fundamental Properties & AI Failures

In Abstract Algebra, we define a Field by properties like Commutativity and Associativity. In Deep Learning, we break them.

The Failure of Commutativity

For scalars, \( ab = ba \). For Matrices, \( \mathbf{A}\mathbf{B} \neq \mathbf{B}\mathbf{A} \).

$$ \text{Let } A = \begin{bmatrix} 0 & 1 \\ 0 & 0 \end{bmatrix}, B = \begin{bmatrix} 0 & 0 \\ 1 & 0 \end{bmatrix} $$ $$ AB = \begin{bmatrix} 1 & 0 \\ 0 & 0 \end{bmatrix}, \quad BA = \begin{bmatrix} 0 & 0 \\ 0 & 1 \end{bmatrix} $$

Impact: In Neural Networks, the order of layers generally cannot be swapped without changing the function entirely.

The Failure of Associativity

For scalars, \( (a+b)+c = a+(b+c) \). In Floating Point Arithmetic, this fails.

# Floating Point Non-Associativity Demo
a = 1e30
b = -1e30
c = 1.0

# Order 1: Large numbers cancel out first
print((a + b) + c) # Output: 1.0

# Order 2: Small number lost in precision
print(a + (b + c)) # Output: 0.0 (Precision Loss!)

2. Broadcasting: Implicit Tensor Algebra

Broadcasting allows binary operations on arrays of different sizes. It is the vectorized equivalent of a nested `for` loop.

Formal Rules

  1. Align dimensions from the right.
  2. If dimensions differ, one of them must be 1.
  3. The dimension with size 1 is stretched to match the other.

3. Einstein Summation (Einsum): A Deep Dive

Proposed by Albert Einstein in 1916 for General Relativity, Einsum is a notation that expresses complex tensor contractions without loops or specific function calls (`matmul`, `transpose`, `dot`).

$$ C_{ik} = \sum_j A_{ij} B_{jk} \implies \text{"ij,jk->ik"} $$

Research Applications

Modern architectures like Transformers use einsum to implement Multi-Head Attention efficiently.

Operation Einsum String Math
Dot Product i,i-> \( \sum_i a_i b_i \)
Matrix Mul ij,jk->ik \( \sum_j A_{ij} B_{jk} \)
Attention bqd,bkd->bqk Batch-Query-Key Mul

The Attention Implementation

import torch

# Batch (b), Heads (h), Seq (t), Dim (d)
Q = torch.randn(32, 8, 128, 64) 
K = torch.randn(32, 8, 128, 64)

# Native implementation: Permute -> Matmul
# scores = torch.matmul(Q, K.transpose(-2, -1))

# Einsum implementation: Clean & Explicit
# "Multiply Q and K along dimension 'd', keep b, h, t"
scores = torch.einsum('b h t d, b h s d -> b h t s', Q, K)

print(scores.shape) # [32, 8, 128, 128]

4. Computational Complexity (Big-O)

Why are LLMs so expensive? The answer lies in the complexity of Tensor Operations.

Matrix Multiplication Cost

Multiplying \( [N \times N] \) by \( [N \times N] \):

  • Standard Algorithm: \( O(N^3) \)
  • Strassen Algorithm: \( O(N^{2.81}) \)
  • Coppersmith-Winograd: \( O(N^{2.373}) \) (Theoretical)

Attention Mechanism Cost

Self-Attention scales quadratically with sequence length \( L \).

$$ \text{Complexity} = O(L^2 \cdot d) $$

This \( L^2 \) scaling is why standard Transformers struggle with very long contexts (e.g., millions of tokens).
