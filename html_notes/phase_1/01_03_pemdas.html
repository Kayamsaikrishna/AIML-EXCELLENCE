3. Order of Operations & Computation Graphs

PEMDAS isn't just a school rule. It is the Execution Schedule of every Neural Network ever built.

1. The Algorithmic Hierarchy (PEMDAS/BODMAS)

Mathematics is a language. Like any language, it needs grammar to avoid ambiguity. Strict rules dictate which operations happen first.

The Hierarchy

  • 1. Parentheses (Groups): \( (a+b) \). This overrides everything. In Code, we use parentheses to force priority.
  • 2. Exponents (Power): \( x^2, \sqrt{x} \). Nonlinearities happen here.
  • 3. Multiplication / Division: \( a \cdot b, a/b \). These essentially modify "Units" or "Scale".
  • 4. Addition / Subtraction: \( a + b, a - b \). These accumulate values.

Why it Matters: The "Ambiguity" Bug

Consider the expression: \( 2 + 3 \times 4 \).

  • If Left-to-Right: \( (2+3) \times 4 = 20 \). (Wrong)
  • If PEMDAS: \( 2 + (3 \times 4) = 14 \). (Correct)

In AI, a single misplaced parenthesis during the "Loss Calculation" step can cause the gradient to flow to the wrong weights, meaning the AI learns nothing.

2. The Engineering View: Computation Graphs

Deep Learning frameworks like PyTorch and TensorFlow don't see equations as text strings. They see them as Directed Acyclic Graphs (DAGs). The "Order of Operations" determines the topology of this graph.

Figure 1: The Forward Pass of a Neuron. Mul must happen before Add for the graph to wire correctly.

The Engineering Application: Forward & Backward Pass

Every time you train a model, two things happen:

  1. Forward Pass (Execution): PyTorch runs the graph in PEMDAS order (Inputs -> Outputs). Computing the loss.
  2. Backward Pass (Autograd): PyTorch runs the graph in Reverse order (Output -> Input) to calculate gradients.

If the Order of Operations is wrong in the Forward Pass, the shape of the graph is wrong, and the Backward Pass calculates "gradients of nonsense".

3. Coding the Graph

Let's see how PyTorch builds this graph implicitly based on the order of your Python code.

// PyTorch: Building the Graph
import torch

# 1. Define the Leaves of the graph (Inputs)
x = torch.tensor([2.0], requires_grad=True)
W = torch.tensor([3.0], requires_grad=True)
b = torch.tensor([5.0], requires_grad=True)

# 2. Forward Pass (Building the Graph)
# Python respects PEMDAS here: W * x is calculated first, then b is added.
z = W * x + b  
# z = (3 * 2) + 5 = 11

# 3. Activation (Next node)
y = torch.relu(z)
# y = 11

print(f"Output: {y.item()}")

# 4. Backward Pass (Traversing the graph)
y.backward()

# 5. Gradients
print(f"Grad W: {W.grad}") # dy/dW = x = 2
print(f"Grad x: {x.grad}") # dy/dx = W = 3
print(f"Grad b: {b.grad}") # dy/db = 1

The "Leaf" Metaphor

In the code above, `x`, `W`, and `b` are called Leaf Nodes. They have no parents in the graph. The operation nodes (`*`, `+`) are internal nodes.

When you call `backward()`, the gradients flow from the Root (`y`) all the way down to the Leaves.
