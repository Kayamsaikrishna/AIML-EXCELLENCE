1. Linear vs. Affine Transformations

Strictly speaking, \( f(x) = mx + b \) is NOT linear if \( b \neq 0 \). It is Affine.

$$ \text{Linearity requires: } f(x+y) = f(x) + f(y) $$ $$ \text{Check: } m(x+y)+b \neq (mx+b) + (my+b) = m(x+y) + 2b $$

Why this matters

In Deep Learning, we call them "Linear Layers" (`nn.Linear`), but they perform Affine transformations. The bias \( b \) allows the hyperplane to shift away from the origin, which is crucial for fitting data that isn't centered at zero.

2. Hyperplanes in High Dimensions

A single linear equation describes a Hyperplane. In 2D, it's a line. In 3D, a plane. In 1000D (Embedding Space), it's a 999D flat surface.

Universal Approximation Theorem

Why do we care about lines? Because Neural Networks are universal function approximators.

The theorem states that a network with just one hidden layer (and non-linear activations) can approximate any continuous function to arbitrary precision.

$$ F(x) = \sum_{i=1}^N v_i \cdot \sigma(w_i x + b_i) $$

Essentially, by summing enough "bent lines" (ReLUs) or "steps" (Sigmoids), we can construct any curve in the universe.

3. Implementing `nn.Linear` from Scratch

Let's peek under the hood of PyTorch's fundamental building block.

import torch
import math

class MyLinear:
    def __init__(self, in_features, out_features):
        # 1. Initialize Weights (Shape: out x in)
        # We use Kaiming Initialization logic here roughly
        std = 1.0 / math.sqrt(in_features)
        self.weight = torch.randn(out_features, in_features) * std
        self.bias = torch.randn(out_features) * std

    def forward(self, x):
        # x shape: [Batch, in_features]
        # y = xW^T + b
        return x @ self.weight.T + self.bias

# Verification
x = torch.randn(10, 5) # Batch of 10, 5 features each
layer = MyLinear(5, 2) # Map 5 -> 2 dimensions
y = layer.forward(x)

print(f"Input Shape: {x.shape}")   # [10, 5]
print(f"Output Shape: {y.shape}")  # [10, 2]
print(f"Sample Output:\n{y[0]}")

4. The Logic of Solving

Solving for \( x \) is the "Inverse" of the forward pass.

    State1 --> Step2["Isolate x"]
    Step2 --> Action2["Divide by 3 (Inverse of *3)"]
    Action2 --> Sol["x = 2"]
